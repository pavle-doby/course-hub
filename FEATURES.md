# Features

Fully implemented features and what is still in progress.

## Fully implemented (all layers: DB → repo → API → contract → OpenAPI → generated hooks → web UI)

- **Auth** — email/password signup, login, signout, refresh. Supabase JWT verified per-request by `handleAuth` on every private route. Signup picks language + theme (defaulted from browser); login/signup responses return saved preferences and apply them. Web: `apps/web/app/auth/[mode]/`.
- **User profile & account** — view/edit profile (firstName, lastName, username, bio), delete own account. `apps/api/src/modules/users/`, `apps/web/app/profile/`.
- **Course authoring** — CRUD, draft→published→archived, public/private visibility, auto-save editor, duplicate. Course cards (creator and learn/explore/home) share `CourseStats`: enrolled students (active enrollments, `enrolledCount` on `GET /v1/courses`, `GET /v1/public/courses`, `GET /v1/enrollments/courses`), rating average + count, and visibility. `apps/api/src/modules/courses/`, `apps/web/app/courses/`.
- **Course thumbnail (Cloudflare R2)** — initialize → direct upload → verify → save/delete. `apps/api/src/modules/courses/`.
- **Topics management** — CRUD, `position` reorder, duplicate. `apps/api/src/modules/topics/`.
- **Lessons management** — CRUD, reorder, duplicate, standalone searchable list with pagination. `apps/api/src/modules/lessons/`, `apps/web/app/lessons/`.
- **Public course catalog** — search + paginated list of published courses; Explore tab with other-creators / exclude-enrolled filters. `apps/web/app/page.tsx`, `apps/web/app/learn/explore/`.
- **Enrollment & enrolled-course reader** — self-enroll (public only; private needs invitation), withdraw, status check, enrolled list, learner detail page with topic/lesson tree, video player, documents. Content stripped server-side for non-enrolled visitors. `apps/api/src/modules/enrollments/`, `apps/web/app/learn/`.
- **Students & creator stats** — student list (avatar, course, dates) + enrollment/student counts. `apps/web/app/students/`.
- **Invitations to private courses** — email invite, one-time share link, revoke, accept, public lookup by token, invite-aware signup/login. `apps/api/src/modules/invitations/`, `apps/web/app/invite/`.
- **Videos (Cloudflare Stream)** — one video per course/topic/lesson, direct upload, webhook-driven `uploading → processing → ready/error`, live progress, playback, delete. `apps/api/src/modules/videos/`.
- **Documents (Cloudflare R2)** — multi-file per course/topic/lesson, direct upload, drag-to-reorder, signed public URLs, delete. `apps/api/src/modules/documents/`.
- **User preferences / settings** — `GET`/`PUT /v1/users/preferences` (language, theme, content behavior); row created in the signup transaction. Settings page applies theme/language live. `apps/api/src/modules/users/`, `apps/web/app/settings/`.
- **Localization (en / sr)** — `@repo/i18n` locales across web UI, error messages, and settings. `packages/i18n/`.
- **Push notifications (Web Push / VAPID)** — per `(user, course, category)` opt-in via `POST`/`DELETE /v1/notifications/subscribe`; device subscriptions in `push_subscriptions`, dead ones pruned on 404/410; copy localized per recipient's `user_preferences.language`. Fire-and-forget triggers: self-enroll → creator (`course_enrolled`), private-course enroll attempt → creator (`private_course_attempt`), published course updated → enrolled users (`course_updated`), new course published → creator's learners (`creator_new_course`). Opt-in prompts after publish (course editor) and after enroll (learn page); `sw.js` handles `push` / `notificationclick`. `apps/api/src/modules/notifications/`, `apps/web/components/notification-prompt.tsx`, `apps/web/services/notifications-service.ts`. Spec: `spec/[done]-task-6.1.md`.
- **Learner progress tracking** — per-lesson status (`todo` / `in_progress` / `done`) set via a dropdown next to the lesson title or a "next step" button (Start lesson → Mark as done; end of lesson on desktop, fixed above the bottom nav on mobile, hidden once done); confetti (`canvas-confetti`) plus a congratulations dialog with fireworks (Thank you / New course → explore) when the course turns done, and on clicks outside interactive elements while it stays done; the creator gets a "Course completed" push (reuses their `course_enrolled` opt-in) when an enrollment newly completes; Enrolled cards show a progress bar with % (`progressPercent` on `GET /v1/enrollments/courses`); topic and course status derived from lesson statuses (icons in the reader tree); course completion stored on `course_enrollments.completedAt` (shown on Students page). Lesson videos resume from the last position, go `in_progress` on play and `done` on end. Reader selection lives in the URL (`?topic=` / `?lesson=`) for sharing; opening a course without one jumps to the last active lesson (`lastLessonId`) unless the course is done, which opens on the course overview. `GET /v1/progress/courses/:publicId`, `PUT /v1/progress/lessons/:lessonId`. `apps/api/src/modules/progress/`, `apps/web/hooks/use-lesson-progress.ts`. Spec: `spec/[done]-task-7.md`.
- **Course reviews** — enrolled learners rate a course 1–5 stars with an optional comment (one editable review per learner, upsert). **Review** button next to Withdraw opens the review dialog; when a course turns done and the learner hasn't reviewed it, the congratulations dialog swaps **Thank you** for **Review**. A **Reviews** link at the bottom of the reader tree opens `/learn/:publicId/reviews` (public, paginated). Average + count are denormalized on `courses.ratingAverage` / `ratingCount` (recomputed in the review-save transaction) and shown on course cards and the course overview. `GET /v1/reviews/courses/:publicId/me`, `PUT /v1/reviews/courses/:publicId`, `GET /v1/public/reviews/courses/:publicId`. `apps/api/src/modules/reviews/`, `apps/web/app/learn/[publicId]/reviews/`. The course creator can reply once per review (write / edit / delete inline on the reviews page; `PUT /v1/reviews/:reviewId/reply`, creator-only). **Needs migration** (`pnpm db:generate --name course_reviews`). Spec: `spec/[done]-task-9.md`.
- **Quizzes** — one quiz per course, topic or lesson (`quizzes`, questions as `jsonb`: `single` / `multiple` / `text`, text not graded). In the editor, a **Quiz** card under the working area opens **Create Quiz** → **AI Create** (Claude, `QUIZ_MODEL` env or `claude-sonnet-5` by default, drafts 3–5 questions from the names and descriptions via `POST /v1/quizzes/:parentType/:parentId/generate`, writes nothing; 20 per user per day, in memory) or **Manual Create**; both fill the same editor form, which also handles **Edit**, **Regenerate with AI** and **Delete**. Enrolled learners take it at the end of the content with the shadcn `Questionnaire`; answers are saved per learner (`quiz_responses`, upsert) and scored on read against the current questions, so the result card shows score, right/wrong and correct answers; **Clear answers** deletes the response. Non-enrolled visitors see an enroll hint. The public `GET` strips correct flags. `apps/api/src/modules/quizzes/`, `apps/web/app/courses/components/quiz/`, `apps/web/app/learn/[publicId]/components/learn-quiz.tsx`. Needs `ANTHROPIC_API_KEY`. **Needs migration**: after the questionnaire → quiz rename run `pnpm db:generate --name rename_questionnaires_to_quizzes` and answer _rename_ (0010 created the old table names). Spec: `spec/[done]-task-10.md`. Coding agents can also read, save (replace whole) and delete quizzes over MCP with `ch_get_quiz` / `ch_save_quiz` / `ch_delete_quiz` (`apps/api/src/modules/quizzes/ai/tools/`); the agent writes the questions, so no platform AI call or daily limit. Spec: `spec/[done]-task-10.1.md`.
- **Content ownership checks** — course update/delete, topic and lesson create/update/delete verify the caller created the course (`coursesService.assertOwnedCourse`, `topicsService.assertOwnedTopic`, `lessonsService.assertOwnedLesson`); another user's id → 403. Spec: `spec/[done]-task-8.0.md`.
- **AI course tools (shared layer)** — typed `courseTools` (`ch_list_my_courses`, `ch_get_course`, `ch_search_public_courses`, `ch_list_enrolled_courses`, `ch_get_enrolled_course`, `ch_create_course_draft`, `ch_add_topic`, `ch_add_lesson`, `ch_update_course`, `ch_update_topic`, `ch_update_lesson`) that call services directly, check ownership, never publish and never delete. `ch_create_course_draft` inserts course → topics → lessons in one transaction (≤ 30 topics, ≤ 30 lessons per topic). Input schemas and `CourseTree` in `packages/contract/src/ai/`. Tools live in each feature module (`apps/api/src/modules/{courses,topics,lessons}/ai/tools/`); `apps/api/src/modules/ai/tools/` holds the `CourseTool` type, `defineTool` and the `courseTools` registry. Spec: `spec/[done]-task-8.0.md`.
- **Enrolled courses in AI agents** — students pull courses they're enrolled in via `ch_list_enrolled_courses` (every active enrollment, with an `aiAccessEnabled` flag) and `ch_get_enrolled_course` (read-only `CourseTree` by `publicId`). The creator opts in per course with the **AI access** switch in the course editor actions (`courses.aiAccessEnabled`, default `false`); otherwise the get tool fails with `ErrorCodeEnrollment.AI_ACCESS_DISABLED`. `apps/api/src/modules/enrollments/ai/tools/`. **Needs migration** (`pnpm db:generate --name course_ai_access`).
- **MCP server for coding agents** — `POST /apix/v1/mcp` (`/apix` = routes used by external systems) (stateless Streamable HTTP, `@modelcontextprotocol/sdk`) exposes the course tools plus the `ch_generate_course`, `ch_review_course` and `ch_research_course` prompts (`mcpPrompts.ts`). Auth via personal access tokens (`ch_pat_…`, only a SHA-256 hash stored in `api_tokens`, `lastUsedAt` throttled to once per minute) checked by `handleTokenAuth`; PATs only work on the MCP route. **OAuth for MCP clients** (claude.ai custom connectors, Claude Code without a header): `/.well-known/oauth-protected-resource` + `/.well-known/oauth-authorization-server` metadata, `WWW-Authenticate` on MCP 401s, stateless dynamic client registration / authorize / PKCE token endpoints under `/apix/oauth/*` (HMAC-signed client IDs and codes, no DB tables), web consent page `/oauth/authorize` → `POST /v1/oauth/approve`. Each approval mints a PAT named after the client, so it shows up and is revoked in AI access. `apps/api/src/modules/oauth/`, `apps/web/app/oauth/authorize/`. Token management: `GET`/`POST /v1/api-tokens`, `DELETE /v1/api-tokens/:id` (revoke), plus the **AI Connect** page (`/ai-connect`, above Settings in nav) with the **AI access** card (create with shown-once token, MCP config and `claude mcp add` snippets; list; revoke). Not part of OpenAPI. `apps/api/src/modules/ai/mcp/`, `apps/api/src/modules/api-tokens/`, `apps/web/app/ai-connect/`. Spec: `spec/[done]-task-8.1.md`.
- **Health endpoint** — `GET /api/v1/health` (infra).

## Partially implemented / in progress

- **Feedback** — `apps/web/app/feedback/` is a stub, no API.
- **Notification history** — `apps/web/app/notifications/` still renders "Coming soon..."; no `notifications` table, list/mark-read endpoints, or nav unread badge yet (planned in `spec/[todo]-task-6.2.md`). No UI to manage/disable existing push opt-ins outside the prompts.
- **Invitation-accept notifications** — accepting an invite enrolls without notifying the creator (intentional for now; `ponytail:` marker in `invitationsService`).
- **Password reset** — forgot-password form only; no submit handler / API endpoint (Supabase `resetPassword` never called).
- **Google OAuth login** — button rendered in login form; no backend wiring.
- **Avatar photo upload** — "Change photo" is an `alert()` placeholder; `users.avatarUrl` exists but no upload flow.
- **Admin user management** — `/api/v1/users*` admin endpoints + hooks exist; no web pages call them.
