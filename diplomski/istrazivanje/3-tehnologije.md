# Jedan ugovor tipova povezuje ceo Course Hub

Tehnologije sistema Course Hub čine lanac u kojem **jedna definicija podataka putuje od baze do oba klijenta**. Tabele se opisuju u Drizzle ORM-u, iz njih drizzle-zod izvodi Zod šeme, zod-to-openapi od istih šema pravi OpenAPI 3.1 dokument, a Orval iz tog dokumenta generiše TanStack Query hook-ove nad Axios-om koje koriste i Next.js 16 web aplikacija i Expo SDK 57 mobilna aplikacija. Sve to živi u jednom pnpm/Turborepo monorepozitorijumu. Na dan 30.09.2026. većina izabranih alata je na aktuelnoj glavnoj verziji ili jednu verziju iza nje. Tri razlike su bitne za poglavlje 3: **TypeScript 7.0** (jul 2026, kompajler prepisan u Go) je noviji od verzije koju projekat verovatno koristi, **pnpm 12** je aktuelan dok projekat traži pnpm 11, a **NativeWind v4** i dalje zahteva Tailwind CSS v3, pa sistem namerno koristi dve glavne verzije Tailwinda. Upravljanje se takođe promenilo: od 24.02.2026. React i React Native pripadaju **React Foundation** pod Linux Foundation, a Tailwind Labs se 09.09.2026. pridružio Shopify-ju. Za monorepo pristup literatura (Potvin i Levenberg 2016; Jaspan i dr. 2018; Brito i dr. 2018; Brousse 2019) se slaže oko prednosti: atomske izmene, jedna verzija zavisnosti, lak refaktoring i vidljivost koda. Kao cenu navodi ulaganje u alate, performanse build-a i slabiju kontrolu pristupa. Za projekat sa jednim autorom i tri aplikacije od tih mana realno ostaje samo potreba za alatima, a nju rešavaju pnpm i Turborepo.

Napomena o metodu: svi izvori u beleškama otvoreni su 30.09.2026. Tvrdnje bez URL-a u beleškama nisu unete u izveštaj i navedene su u odeljku 5.

## 1. Kratak pregled nalaza po grupama

### 1.1 Ugovor i API: od Zod šeme do generisanog hook-a

Grupa „ugovor i API“ je osnova tvrdnje o tipskoj bezbednosti sistema. **TypeScript** (Microsoft) dodaje statički, strukturni sistem tipova nad JavaScript-om. Aktuelna glavna verzija je **7.0 od 08.07.2026**, prvi nativni kompajler u Go-u, „a 10x faster native port of TypeScript“, dok je 6.0 (23.03.2026) poslednje izdanje na staroj JS bazi ([TypeScript DevBlogs](https://devblogs.microsoft.com/typescript/)). **Zod 4** je stabilan (poslednje izdanje v4.6.5, 13.09.2026) i donosi ugrađeni `z.toJSONSchema()` i registre metapodataka ([zod.dev/v4](https://zod.dev/v4); [GitHub releases](https://github.com/colinhacks/zod/releases)). Na tome radi **zod-to-openapi**, koji sa `registerPath` i `OpenApiGeneratorV31` pravi OpenAPI 3.1 dokument i u novijim verzijama zahteva Zod v4 ([README](https://github.com/asteasolutions/zod-to-openapi)). **OpenAPI 3.1.0** (15.02.2021) je važan jer je njegov Schema Object nadskup JSON Schema 2020-12, pa se Zod šeme u njega preslikavaju gotovo bez gubitaka. Novija verzija 3.2.0 (19.09.2025) postoji, ali prelazak nije potreban ([OAS 3.1.0](https://spec.openapis.org/oas/v3.1.0.html); [OAS 3.2.0](https://spec.openapis.org/oas/v3.2.0.html)). Na klijentskoj strani **Orval v8** (poslednje izdanje v8.39.0) generiše React Query hook-ove ([orval.dev](https://orval.dev/)). **TanStack Query v5** (5.104.0, 26.09.2026) upravlja serverskim stanjem, a **Axios** je HTTP sloj sa interceptorima ([TanStack Releases](https://github.com/TanStack/query/releases); [axios](https://github.com/axios/axios)). Teorijsku osnovu čine **Fieldingova disertacija** (UC Irvine, 2000) za REST i **RFC 7519** (IETF, 2015) za JWT. Ovi izvori su trajni i najpogodniji za citiranje. Treba pošteno napisati da Course Hub API poštuje ograničenja klijent-server, stateless i uniformni interfejs, ali ne i HATEOAS, kao i većina „REST-olikih“ API-ja.

**TypeScript.** JavaScript sa dodatnim slojem, sistemom tipova: „TypeScript offers all of JavaScript's features, and an additional layer on top of these“. Njegov osnovni princip je strukturno tipiziranje, pa se tipovi porede po obliku („shape“) vrednosti ([TS handbook](https://www.typescriptlang.org/docs/handbook/typescript-in-5-minutes.html)). Održava ga Microsoft, a izdanja objavljuje Daniel Rosenwasser na DevBlogs-u. Hronologija: 5.9 (01.08.2025), 6.0 (23.03.2026), 7.0 Beta (21.04.2026), 7.0 RC (18.06.2026), **7.0 (08.07.2026)** ([DevBlogs](https://devblogs.microsoft.com/typescript/)). Za rad je bitno da se ceo ugovor (`@repo/contract`) izražava tipovima koje dele API, web i native.

**Zod.** „TypeScript-first schema validation with static type inference“. Šema se definiše jednom, `.parse()` proverava nepoznate podatke, a rezultat nosi ispravan TS tip. Jezgro ima oko 2 kB gzip i nema zavisnosti ([zod.dev](https://zod.dev/)). Autor je Colin McDonnell. Zod 4 u odnosu na Zod 3 parsira stringove 14,71 puta brže, a objekte 6,5 puta brže, paket je 2,3 puta manji, a uvodi Zod Mini, `z.toJSONSchema()` i `.meta()` ([Zod 4 release notes](https://zod.dev/v4)).

**REST.** Roy T. Fielding je REST definisao u 5. poglavlju disertacije kao „a hybrid style derived from several of the network-based architectural styles“. Ograničenja su: klijent-server, stateless, keš, uniformni interfejs (identifikacija resursa, manipulacija kroz reprezentacije, samoopisne poruke, HATEOAS), slojeviti sistem i opcioni code-on-demand ([Fielding, pogl. 5](https://ics.uci.edu/~fielding/pubs/dissertation/rest_arch_style.htm)).

**OpenAPI 3.1.** „A standard, programming language-agnostic interface description for HTTP APIs“. Specifikacija je objavljena 15.02.2021. pod okriljem OpenAPI Initiative (Linux Foundation) ([OAS 3.1.0](https://spec.openapis.org/oas/v3.1.0.html)). Najnovije verzije su 3.1.2 (u grani 3.1) i 3.2.1 (ukupno) ([spec.openapis.org/oas](https://spec.openapis.org/oas/)).

**zod-to-openapi.** Biblioteka firme Astea Solutions: „A library that uses zod schemas to generate an Open API Swagger documentation.“ Ključni API su `OpenAPIRegistry.registerPath`, `extendZodWithOpenApi(z)` i `.openapi("Ime")`. `OpenApiGeneratorV31` umesto `nullable: true` koristi niz tipova `type: ['string','null']` ([README](https://github.com/asteasolutions/zod-to-openapi)). Grana 7.3.4 za Zod v3 više nije aktivno podržana.

**Orval.** „Transform your OpenAPI specs into type-safe clients, mocks, and validators.“ Podržava React Query, SWR, Vue/Svelte/Solid Query, Angular, Axios, Fetch, Zod, Hono i MSW. Razvija ga zajednica pod organizacijom orval-labs ([orval.dev](https://orval.dev/); [GitHub releases](https://github.com/orval-labs/orval/releases)).

**TanStack Query.** Biblioteka koja olakšava „fetching, caching, synchronizing and updating server state“. Pravi razliku između serverskog stanja (udaljeno, asinhrono, deljeno vlasništvo, može zastareti) i klijentskog stanja. Rešava keširanje, deduplikaciju zahteva, osvežavanje u pozadini, paginaciju i garbage collection ([Overview](https://tanstack.com/query/latest/docs/framework/react/overview)).

**Axios.** „Promise based HTTP client for the browser and node.js“. Ima interceptore zahteva i odgovora, transformaciju podataka, otkazivanje zahteva, automatski JSON i XSRF zaštitu. Zvanični sajt je sada axios.rest ([axios/axios](https://github.com/axios/axios)). U Course Hub-u je Axios instanca mutator za Orval hook-ove.

**JWT.** „A compact, URL-safe means of representing claims to be transferred between two parties.“ Claims su payload JWS strukture (potpisane ili MAC) ili JWE strukture (šifrovane). Standard su napisali M. Jones, J. Bradley i N. Sakimura kao RFC 7519, Standards Track, maj 2015 ([RFC 7519](https://www.rfc-editor.org/rfc/rfc7519)).

### 1.2 Server i podaci: LTS runtime, relaciona baza i serverless mediji

Serverski deo je u potpunosti na podržanim, produkcionim linijama. **Node.js** je „an asynchronous event-driven JavaScript runtime“. U septembru 2026. v26 je Current, a v22 (Jod) i v24 (Krypton) su LTS, pa uslov `node >=22` pokriva sve podržane linije ([Node.js About](https://nodejs.org/en/about); [Releases](https://nodejs.org/en/about/previous-releases)). Od Node.js 27 izdanja postaju godišnja. **Express 5** je zvanično najavljen 15.10.2024, a od 31.03.2025. (verzija 5.1.0) je podrazumevan na npm-u. Najvažnija novina za Course Hub je da ruter hvata odbijene promise-e iz `async` handler-a kao `next(err)`, pa tipizovane greške stižu do centralnog error middleware-a bez try/catch omotača ([Express v5](https://expressjs.com/en/blog/2024-10-15-v5-release); [5.1.0](https://expressjs.com/en/blog/2025-03-31-v5-1-latest-release)). **PostgreSQL 18** (18.6) je aktuelna stabilna verzija, a 19 je u beti ([Versioning](https://www.postgresql.org/support/versioning/)). **Supabase** daje punu Postgres bazu i Auth sa kratkotrajnim JWT access tokenom i jednokratnim refresh tokenom ([Supabase Sessions](https://supabase.com/docs/guides/auth/sessions)). **Drizzle ORM** je stabilan na liniji 0.45.x, a 1.0 je tek u RC fazi, što treba napomenuti jer rad oslanja šemu na biblioteku pre verzije 1.0 ([Drizzle Releases](https://github.com/drizzle-team/drizzle-orm/releases)). **Cloudflare Stream** preuzima enkodovanje i isporuku videa preko HLS/DASH manifesta, a **R2** čuva ostale fajlove bez naknade za odlazni saobraćaj ([Stream](https://developers.cloudflare.com/stream/); [R2](https://developers.cloudflare.com/r2/)). **Railway** hostuje API i web kao dva servisa. O njemu je potvrđen samo samoopis iz dokumentacije ([Railway Docs](https://docs.railway.com/)).

**Node.js.** Petlja događaja (event loop) je deo samog okruženja. Gotovo nijedna funkcija ne radi I/O direktno, pa proces ne blokira, a HTTP je „first-class citizen“ ([About](https://nodejs.org/en/about)). Svako izdanje je 6 meseci Current, zatim prelazi u Active pa Maintenance LTS, sa ukupno 30 meseci podrške. Za produkciju se preporučuju samo LTS linije ([Releases](https://nodejs.org/en/about/previous-releases)).

**Express 5.** Najavu su 15.10.2024. potpisali Wes Todd i Express Technical Committee. Izmene: minimalno Node.js 18, nova sintaksa ruta u path-to-regexp (`{:name}`, `*name`, bez regex podizraza zbog ReDoS-a) i uklonjeni zastareli API-ji (`app.del`, `res.send(status, body)`…) ([Express v5](https://expressjs.com/en/blog/2024-10-15-v5-release)). Faza ACTIVE traje najmanje 12 meseci, a EOL za 5.x je „no sooner than 2027-04-01“ ([5.1.0](https://expressjs.com/en/blog/2025-03-31-v5-1-latest-release)). Najnovije izdanje je 5.2.1 ([GitHub](https://github.com/expressjs/express/releases)).

**PostgreSQL.** „A powerful, open source object-relational database system that uses and extends the SQL language“. Nastao je iz projekta POSTGRES na UC Berkeley (1986), ACID-usklađen je od 2001, a održava ga PostgreSQL Global Development Group ([About](https://www.postgresql.org/about/)). Svaka glavna verzija ima 5 godina podrške. Verzija 18 je izašla 25.09.2025. i podržana je do 14.11.2030 ([Versioning](https://www.postgresql.org/support/versioning/)). Za kvizove je bitan tip `jsonb`: binarni zapis, brža obrada, GIN indeksi i operator `@>`. Dokumentacija ga preporučuje za većinu aplikacija ([JSON Types](https://www.postgresql.org/docs/current/datatype-json.html)).

**Supabase.** „Every project is a full Postgres database“. Uz bazu nudi Auth, Storage, Realtime i Edge Functions ([Features](https://supabase.com/docs/guides/getting-started/features)). Access token podrazumevano traje 1 h i nosi claim `session_id`. Refresh token se može iskoristiti jednom, a ponovna upotreba van prozora od 10 s opoziva celu sesiju ([Sessions](https://supabase.com/docs/guides/auth/sessions)). JWT nosi claims `sub`, `role`, `exp` i `iss`. Backend ga verifikuje preko `/.well-known/jwks.json` (asimetrični ključevi), a deljeni HS256 ključevi se ne preporučuju ([JWTs](https://supabase.com/docs/guides/auth/jwts)). Na tome radi `handleAuth` middleware u Course Hub-u.

**Drizzle ORM.** „A headless TypeScript ORM with a head“, bez zavisnosti, sa geslom „If you know SQL, you know Drizzle“. Ima i SQL-like i relacioni API, a relacioni upit uvek proizvodi tačno jedan SQL upit ([Overview](https://orm.drizzle.team/docs/overview)). drizzle-kit ima komande `generate`, `migrate`, `push` i `pull` ([Migrations](https://orm.drizzle.team/docs/migrations)). drizzle-zod nudi `createSelectSchema`, `createInsertSchema` i `createUpdateSchema`, a noviji Drizzle ga integriše kao `drizzle-orm/zod` ([drizzle-zod](https://orm.drizzle.team/docs/zod)). Course Hub koristi zaseban `drizzle-zod@0.8.3` sa patch-om.

**Cloudflare Stream.** „Serverless live and on-demand video streaming with adaptive bitrate encoding and global delivery“. Kodira u H.264 sa adaptivnim bitrate-om od 360p do 1080p ([Stream](https://developers.cloudflare.com/stream/)). Isporučuje HLS (`.m3u8`) i DASH (`.mpd`) manifeste ([Own player](https://developers.cloudflare.com/stream/viewing-videos/using-own-player/)). Kod direct creator upload-a backend dobija jednokratni `uploadURL`, a klijent otprema video direktno, dok se za fajlove veće od 200 MB koristi tus ([Direct uploads](https://developers.cloudflare.com/stream/uploading-videos/direct-creator-uploads/)). Webhook se potpisuje HMAC-SHA256 potpisom nad `time + "." + telo`, što objašnjava raw-body rutu u API-ju ([Webhooks](https://developers.cloudflare.com/stream/manage-video-library/using-webhooks/)).

**Cloudflare R2.** „Object storage for all your data“, bez „costly egress bandwidth fees“ ([R2](https://developers.cloudflare.com/r2/)). Presigned URL-ovi se potpisuju sa AWS SigV4 lokalno, važe od 1 s do 7 dana, podržavaju GET, HEAD, PUT i DELETE (ne POST) i rade samo na S3 API domenu ([Presigned URLs](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)).

**Railway.** „An all-in-one intelligent cloud provider that makes it easy to provision infrastructure, develop locally, and deploy to the cloud“ ([Railway Docs](https://docs.railway.com/)). Course Hub se tamo postavlja kao dva servisa (API i web), prema `README.deploy.md` u repozitorijumu.

### 1.4 Monorepo: literatura potvrđuje izbor, alati ga čine izvodljivim

Akademska literatura o monorepozitorijumima je malobrojna i zasnovana uglavnom na iskustvu velikih kompanija, ali su nalazi konzistentni. **Potvin i Levenberg (2016)** opisuju Google-ovu jedinstvenu bazu koda koju koriste desetine hiljada programera ([Google Research](https://research.google/pubs/why-google-stores-billions-of-lines-of-code-in-a-single-repository/)). **Jaspan i dr. (2018)** su anketom i analizom logova utvrdili da monorepo donosi vidljivost koda, ponovnu upotrebu i centralizovano ažuriranje zavisnosti, a da više repozitorijuma daje slobodu izbora alata, bolju bezbednosnu kontrolu i stabilnost. Ključni zaključak je da je kompatibilnost alata presudna za preferencije inženjera ([Google Research](https://research.google/pubs/pub47040/)). **Brito, Terra i Valente (2018)** u multivokalnom pregledu literature definišu monorepo kao jedan repozitorijum sa više projekata koji dele zavisnosti. Kao prednosti navode pojednostavljene zavisnosti, koordinaciju izmena i refaktoring, a kao izazove zdravlje koda, složenost i ulaganje u alate ([arXiv](https://arxiv.org/abs/1810.09477)). **Brousse (2019, Adobe)** tvrdi da monorepo može „drive high efficiency and enhanced product quality through improved team cognition“ i da mnoge firme imaju polyrepo zbog organskog rasta, a ne svesnog izbora ([Programming 2019](https://2019.programming-conference.org/details/icw-2019-papers/5/The-Issue-Of-Source-Code-Repository-Management-In-Large-Enterprises)). **Lentner (2023)** upozorava da nezavisan deploy postaje složeniji i da akademska zajednica ne treba prosto da kopira industriju ([Zenodo](https://zenodo.org/records/10426338)). Industrijska definicija sa monorepo.tools (sajt održava Nx) dodaje da je dobar monorepo „the opposite of monolithic“ ([monorepo.tools](https://monorepo.tools/)). Za Course Hub, gde promena Zod šeme mora u istom commit-u da stigne u API, web i Expo, atomske izmene nisu apstraktna prednost nego uslov rada. **pnpm** (store sa hard linkovima, strogi `node_modules`, `workspace:` protokol, catalogs) i **Turborepo** (graf taskova, keš po hešu ulaza, `--filter`) su alati koji tu prednost čine izvodljivom, što je u skladu sa zaključkom Jaspan i dr. da su alati jednako važni kao struktura.

**pnpm.** „All the files are saved in a single place on the disk … hard-linked from that single place.“ Zato pnpm pravi strogi `node_modules` sa symlinkovima samo za direktne zavisnosti, bez fantomskih zavisnosti ([Motivation](https://pnpm.io/motivation)). Workspace se definiše u `pnpm-workspace.yaml`, a `workspace:*` se razrešava isključivo lokalno ([Workspaces](https://pnpm.io/workspaces)). Catalogs centralizuju verzije: „It's usually desirable to have only one version of a dependency in a workspace“ ([Catalogs](https://pnpm.io/catalogs)). Aktuelne grane su v12.8.2, v11.28.3 i v10.34.6 ([GitHub releases](https://github.com/pnpm/pnpm/releases)). Course Hub koristi pnpm 11 sa `nodeLinker: hoisted` zbog Expo-a, što je svesni kompromis sa strogim `node_modules`.

**Turborepo.** „Build system optimized for JavaScript and TypeScript, written in Rust“, pod MIT licencom, održava ga Vercel ([GitHub](https://github.com/vercel/turborepo)). `turbo.json` definiše `tasks` sa `dependsOn`, `outputs`, `inputs`, `cache`, `persistent` i `env`. Oznaka `^build` znači da se prvo grade zavisnosti, „working its way back to the 'top'“ ([Configuration](https://turborepo.dev/docs/reference/configuration)). Keš se zasniva na hešu ulaza, lokalno u `.turbo/cache` ili udaljeno ([Caching](https://turborepo.dev/docs/crafting-your-repository/caching)). CI pokreće `turbo build --filter=api...`, pa se gradi samo servis i njegovi interni paketi. Alternative su **Nx** (graf projekata, „affected“ komande, pluginovi) ([nx.dev](https://nx.dev/docs/getting-started/intro)) i **Lerna**, fokusirana na objavljivanje paketa i danas „Powered by Nx“ ([lerna.js.org](https://lerna.js.org/)). Turborepo je jednostavniji jer se oslanja na postojeće `package.json` skripte.

## 3. Prednosti i nedostaci monorepo pristupa

| Aspekt | Prednost / nedostatak | Relevantnost za Course Hub | Izvor |
|---|---|---|---|
| Upravljanje zavisnostima | **Prednost**: pojednostavljene zavisnosti, jedna verzija u celom repozitorijumu | pnpm catalogs i overrides (jedna verzija React-a za Expo) | Brito i dr. 2018 ([arXiv](https://arxiv.org/abs/1810.09477)); [pnpm Catalogs](https://pnpm.io/catalogs) |
| Atomske izmene | **Prednost**: jedan commit menja više projekata istovremeno | Promena `@repo/contract` + regenerisan `api-client` + API + web + native | [monorepo.tools](https://monorepo.tools/); Brito i dr. 2018 |
| Refaktoring | **Prednost**: lak refaktoring velikih razmera | Preimenovanje polja šeme vidljivo u svim klijentima kroz TS grešku | Brito i dr. 2018 ([arXiv](https://arxiv.org/abs/1810.09477)) |
| Vidljivost i ponovna upotreba | **Prednost**: bolja vidljivost koda, lakša ponovna upotreba API-ja | `@repo/shared`, `@repo/ui-theme`, `@repo/i18n` bez objavljivanja na npm | Jaspan i dr. 2018 ([Google Research](https://research.google/pubs/pub47040/)) |
| Deljenje koda | **Prednost**: bez troška objavljivanja paketa, bag se ispravlja jednom | Interni paketi preko `workspace:*` | [monorepo.tools](https://monorepo.tools/) (vendorski izvor, Nx) |
| Timska kognicija | **Prednost**: manje barijera između timova, veća efikasnost i kvalitet | Ograničeno (jedan autor) | Brousse 2019 ([Programming '19](https://2019.programming-conference.org/details/icw-2019-papers/5/The-Issue-Of-Source-Code-Repository-Management-In-Large-Enterprises)) |
| Centralizacija i standardizacija | **Prednost/tenzija**: konvencije se nameću svima, na račun slobode izbora alata | Zajednički ESLint/Prettier/TS config; web Tailwind 4 i native Tailwind 3 pokazuju granicu | Brito i dr. 2018; Jaspan i dr. 2018 |
| Ulaganje u alate | **Nedostatak**: potrebni specijalizovani alati za build i razvoj | Rešeno pnpm-om i Turborepo-om | Brito i dr. 2018; Jaspan i dr. 2018 |
| Složenost i zdravlje koda | **Nedostatak**: složenija baza koda, rizik po zdravlje koda | Umereno; granice paketa i barrel izvozi to ublažavaju | Brito i dr. 2018 ([arXiv](https://arxiv.org/abs/1810.09477)) |
| Bezbednost / kontrola pristupa | **Nedostatak**: polyrepo daje bolju bezbednosnu kontrolu | Nije relevantno (jedan autor) | Jaspan i dr. 2018 ([Google Research](https://research.google/pubs/pub47040/)) |
| Stabilnost | **Nedostatak**: polyrepo daje veću stabilnost (verzionisane zavisnosti) | Promena deljenog paketa odmah pogađa sve aplikacije | Jaspan i dr. 2018 |
| Nezavisan deploy | **Nedostatak**: složeniji nezavisan deploy komponenti | Dva Railway servisa + `--filter` u CI-ju | Lentner 2023 ([Zenodo](https://zenodo.org/records/10426338)) |
| Performanse build-a, veličina | **Nedostatak** (u velikim razmerama): spor build, veliki checkout | Mala baza koda; Turborepo keš | Potvin i Levenberg 2016, preko sekundarnog izvora ([Wikipedia](https://en.wikipedia.org/wiki/Monorepo)); [Turborepo Caching](https://turborepo.dev/docs/crafting-your-repository/caching) |

Istraživači sa obe strane priznaju da se dobar deo prednosti monorepozitorijuma (pretraga, upravljanje zavisnostima) uz dobre alate može postići i u multi-repo okruženju ([AcaWiki sažetak Jaspan i dr.](https://acawiki.org/Advantages_and_Disadvantages_of_a_Monolithic_Repository)). Zato argument u radu ne treba da glasi „monorepo je bolji“, nego „za jedan tipizovani ugovor koji dele tri aplikacije, monorepo uklanja korak objavljivanja i verzionisanja ugovora“.

## Zaključak

Za poglavlje 3 najvažniji uvid nije pojedinačna tehnologija, već to da su izbori međusobno uslovljeni. Zod 4 omogućava zod-to-openapi sa OpenAPI 3.1, a 3.1 je usklađen sa JSON Schema. Zato Orval može da generiše jedan klijent za oba frontend-a, i zato monorepo prestaje da bude stvar ukusa i postaje uslov da ugovor ostane jedan izvor istine. Poglavlje je najjače ako prati taj lanac (baza → ugovor → API → klijent) umesto abecednog spiska alata.

Drugi uvid se tiče pisanja o verzijama. Tri zaostajanja (TS 7, pnpm 12, React 19.3 / RN 0.87) nisu propust nego posledica ograničenja ekosistema: Next.js i Expo određuju verziju React-a, NativeWind 4 određuje Tailwind 3, a Expo određuje React Native. Rad deluje zrelije ako to eksplicitno obrazloži, uz napomenu da React i React Native od 2026. imaju novog vlasnika (React Foundation), što je relevantno za procenu dugoročne održivosti izabranog steka.
